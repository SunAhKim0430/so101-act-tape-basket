# 실험 보고서: SO-101 ACT로 테이프를 집어 바구니에 넣기

작성일: 2026-11-11 · LeRobot 0.6.1, ACT

## 요약

- **1차 실험은 실패했습니다.** 원인은 학습 길이가 아니라 데이터였습니다. 정지 프레임이 65%였고, 손목 카메라만 썼고, 10fps에 한 번 예측하면 10초 동안 그대로 움직이는 설정이었습니다.
- **2차 실험은 15개 에피소드만으로 성공했습니다.** 고정 카메라 1대, 30fps, 작업이 끝나면 바로 녹화 종료, 일정한 시작 자세, 한 자리에서만 녹화(작업을 좁힘)를 적용했습니다.
- **실물 시연에서 한계 세 가지를 확인했습니다.**
  - 테이프를 학습 때보다 옆에 두면 팔이 조금 돌다가 못 집었습니다.
  - 테이프를 세워 두면 이미 잡았다고 착각해 놓는 동작을 반복했습니다.
  - 정해진 시간(40초)이 다 되면 테이프를 든 채로 시작 자세로 돌아갔습니다.
- 앞의 두 한계는 **학습 데이터에 없던 상황**에서 생깁니다. 세 번째는 모델이 아니라 **실행 스크립트의 시간 제한**에서 생깁니다.

## 1. 실험 개요

| 항목 | 내용 |
|---|---|
| 작업 | 책상 위 노란 박스 테이프를 집어 옆의 종이 상자(바구니)에 넣고 시작 자세로 돌아오기 |
| 작업 문장 | `Grab the yellow tape and put in the basket` |
| 로봇 | SO-101 팔로워 + 리더(시연용). 리더를 손으로 움직여 팔로워를 조종하며 녹화 |
| 정책 | LeRobot ACT: 카메라 영상 + 관절 6개 → 앞으로의 관절 목표 `chunk_size`개를 한 번에 예측 |
| 학습 | A100, batch 8, ACT 기본 설정 (ResNet18, VAE, lr 1e-5) |
| 실행 | Windows 노트북 CPU, `lerobot-rollout`, 40초 |

진행 순서: 녹화(로봇 PC) → 데이터 점검·합치기·학습(GPU 서버) → 모델을 로봇 PC로 옮겨 실행. 단계별 방법은 [docs/](.)에 있습니다.

## 2. 1차 실험이 실패한 이유

1차 실험은 50개 에피소드로 학습했지만 실물 로봇에서 작업을 하지 못했습니다. 실행 영상은 남기지 않아서, 아래는 **데이터와 학습 기록을 분석한 결과**입니다.

| 항목 | 1차 (실패) | 2차 (성공) | 영향 |
|---|---|---|---|
| 에피소드 | 50개, **모두 정확히 60초** | 15개, 20~27초 | 1차는 작업이 끝나도 녹화 종료 키(`n`)를 누르지 않음 |
| 정지 프레임 비율 | **65%** | 24% | 1차는 데이터의 2/3가 "가만히 있기" |
| 실제 작업 길이 (중앙값) | 18.8초 | 17.6초 | 작업 자체는 같은 길이 |
| fps | **10** | 30 | 10fps는 동작이 거칠게 기록됨 |
| 카메라 | **손목 1대** | 앞쪽 위 고정 1대 | 손목 카메라로는 시작 자세에서 바구니가 안 보임 |
| chunk (한 번 예측한 동작의 길이) | 100 = **10초** | 100 = 3.3초 | 1차는 예측 한 번으로 10초 동안 눈을 감고 움직임 |
| 시작 자세 편차 (관절별 표준편차) | 7.5 / 7.4 / 1.1 / 9.9 / 8.6 / 9.2° | 7.8 / 0.1 / 0.4 / 0.3 / 5.0 / 0.3° | 2차는 어깨 회전을 뺀 관절이 거의 일정 |
| 이상 에피소드 | 동작이 전혀 없는 에피소드 1개 등 | 없음 | |
| 학습 | 100k step, loss 0.073 | 50k step, loss 0.044 | **둘 다 정상 수렴** → 학습 길이는 원인이 아님 |

관절 순서: 어깨 회전(shoulder_pan) / 어깨 들기 / 팔꿈치 / 손목 굽힘 / 손목 회전 / 그리퍼

원인 정리
1. **정지 프레임 65%.** 60초를 꽉 채워 녹화해서 작업이 끝난 뒤 40초 가까이 가만히 있는 장면이 들어갔습니다. 모방 학습은 보여 준 행동의 비율까지 따라 하므로 "멈춰 있기"가 가장 많이 배운 행동이 됩니다. 시작 자세에서 출발하지 않거나 중간에 멈출 수 있습니다.
2. **손목 카메라만 사용.** 시작 자세에서 손목 카메라에는 바구니가 보이지 않습니다. "어디로 옮길지"를 영상에서 알 수 없습니다.
3. **10fps에 chunk 100 = 10초.** ACT 논문은 50Hz에 chunk 100(2초)을 썼고, 저자는 chunk를 1초 정도로 권합니다. 10초 동안 카메라를 다시 보지 않고 움직이면 작은 오차를 고칠 기회가 없습니다.
4. **시작 자세가 제각각.** 같은 화면에서 출발해도 관절 값이 달라 학습이 어려워집니다.

## 3. 2차 실험이 성공한 이유

2차 실험은 15개 에피소드(약 6분 분량)로 학습한 모델(chunk 100, 50k step)이 실물 로봇에서 테이프를 집어 바구니에 넣었습니다.
(실행 횟수와 성공률은 기록하지 않았습니다. 바꾼 것을 하나씩 따로 시험하지 않았기 때문에, 아래는 1차와 비교해 **바꾼 것과 그 근거**입니다.)

### 3-1. 데이터를 바꿨다
- **고정 카메라를 앞쪽 위에서 약 45°로.** 한 화면에 테이프, 바구니, 그리퍼가 모두 보입니다. 기준은 "카메라 화면만 보고 사람이 이 작업을 할 수 있는가"였습니다.
- **30fps, 작업이 끝나면 바로 `n`.** 에피소드가 20~27초로 줄었고 정지 프레임이 65% → 24%가 됐습니다. 남은 정지는 대부분 녹화 시작 직후 3~5초입니다.
- **시작 자세를 하나로.** 어깨 회전을 뺀 관절의 편차가 1° 미만이 됐습니다.
- **실패한 시연은 버림(`r`).** 15개 모두 테이프가 바구니에 들어간 시연입니다. 녹화 후 시작·잡기·끝 장면을 모아 확인했습니다.

### 3-2. 작업을 좁혔다
- 15개 모두 테이프를 **거의 같은 자리**에 두고 녹화했습니다. 화면에서 테이프 중심의 표준편차는 2~10px(640×480 기준)이고, 테이프 지름은 약 100px입니다.
- LeRobot 가이드도 첫 데이터는 변화를 적게 하라고 권합니다. 한 자리라면 15개로도 충분했습니다. 대신 이 선택이 4-1의 한계로 이어집니다.

### 3-3. 녹화·학습 과정의 오류를 미리 막았다
- **저장 중 키 입력 문제.** 에피소드를 저장하는 동안(약 1분) 누른 `n` 때문에 다음 에피소드가 빈 채로 끝나 세션 전체가 멈췄습니다. 녹화 스크립트(`record.py`)가 이런 키를 무시하게 고쳤습니다.
- **학습 전 자동 점검.** 파일 누락, fps, 카메라 구성, 영상 디코딩, 정지 비율, 시작 자세 편차를 점검했습니다 (`train.sh`, `check_dataset.py`, `ep_stats.py`).
- **세션 사이 카메라 이동 감지.** 녹화 도중 카메라가 한 번 움직인 것(약 35px)을 찾아냈습니다 (`cam_shift.py`). 시연에 성공한 15개 모델은 움직이기 전 화면만 썼습니다.

### 3-4. 실행 설정을 맞췄다
- **chunk 100 = 3.3초.** 1차의 10초보다 훨씬 자주 화면을 다시 봅니다.
- **`n_action_steps` 100 (한 번 예측한 동작을 다 쓰고 다시 예측).** 노트북 CPU에서는 예측 한 번에 0.1~0.25초가 걸리고 그동안 팔이 멈춥니다(서버 CPU 측정 86~237ms). 1초마다 예측하면 1초마다 멈칫하고, 3.3초마다 예측하면 덜 멈칫해 동작이 더 부드러웠습니다.
- 한 스텝(1/30초)에 관절당 최대 10°로 제한했습니다 (`max_relative_target`).

## 4. 실물 시연에서 확인한 한계

시연 모델(15개, chunk 100, 50k step, `n_action_steps` 100)로 조건을 바꿔 실행하며 관찰한 내용입니다.

### 4-1. 테이프가 학습 때보다 옆에 있으면 못 집음

**관찰:** 테이프를 학습 때 자리보다 옆에 두자, 팔이 오른쪽으로 조금 돌긴 했지만 충분히 돌지 못해 테이프를 집지 못했습니다.

**분석:**
- 학습 데이터 15개에서 **테이프를 잡는 순간의 어깨 회전 각도는 −1°~14°(평균 7°)**였습니다. 잡는 시점은 그리퍼가 열렸다가 닫히는 순간으로 계산했습니다. 테이프 위치도 화면에서 거의 같았습니다.
- 모델은 "테이프 위치가 달라지면 팔을 그만큼 더 돌린다"는 관계를 배울 기회가 없었습니다. 위치가 다른 예시가 없으니 "테이프는 늘 여기 있고, 팔은 이만큼 돈다"를 외운 셈입니다.
- 화면 속 테이프가 옮겨진 것에는 반응해서 조금 돌았지만, 본 적 없는 각도까지 늘려서 움직이지는 못했습니다. 모방 학습(behavior cloning)은 보여 준 범위 안에서는 잘 따라 하지만, 그 바깥으로 넓혀 가는 것은 약합니다.

**개선:**
- 테이프 자리를 여러 곳으로 나눠 녹화합니다. LeRobot 가이드 기준은 자리마다 10개, 전체 50개 이상입니다. 집어야 할 범위의 **양 끝 자리를 반드시 포함**합니다.
- 자리마다 개수를 비슷하게 맞춰 한 자리에 치우치지 않게 합니다.

### 4-2. 테이프가 세워져 있으면 이미 잡았다고 착각해 놓는 동작을 반복함

**관찰:** 테이프를 바닥에 눕히지 않고 세워 두자, 로봇이 이미 테이프를 잡았다고 인식한 것처럼 놓는 동작을 반복했습니다.

**분석:**
- 학습 데이터에서 테이프는 처음에 **항상 바닥에 눕혀져** 있었습니다(구멍이 위를 향함). 테이프가 **세워진 모습**(옆에서 본 고리)은 그리퍼가 테이프를 들고 바구니로 옮길 때만 나옵니다. [예시 영상 장면](../media/example_episode.jpg)에서 첫 장면(누운 테이프)과 세 번째·네 번째 장면(들고 옮기는 테이프)을 비교하면 보입니다.
- ACT는 **지금 보이는 화면과 관절 값만으로** 다음 동작을 정합니다. "방금 잡았다"는 기억이 없습니다. 세워진 테이프가 "들고 옮기는 중"의 화면과 비슷해 보여서, 작업의 뒷부분인 바구니 쪽에서 그리퍼를 여는 동작을 고른 것으로 보입니다.
- 놓는 동작을 해도 화면에는 여전히 세워진 테이프가 보이니 같은 판단을 다시 하고, 그래서 반복됩니다.

**개선:**
- 세워진 테이프를 집는 시연을 따로 녹화해 넣습니다 (눕힌 것과 세운 것을 섞어서).
- 손목 카메라를 추가해 그리퍼 안에 테이프가 있는지를 정책이 직접 볼 수 있게 합니다.
- 녹화 데이터에 없는 물체 자세는 실행할 때도 피합니다.

### 4-3. 시간이 다 되면 테이프를 든 채로 시작 자세로 돌아감

**관찰:** 정해진 시간이 지나자, 테이프를 들고 있는데도 로봇이 바로 원래 자세로 돌아가려고 했습니다.

**분석: 모델이 아니라 실행 스크립트의 동작입니다.**
- `5_rollout.bat`은 `lerobot-rollout --duration=40`(`config.bat`의 `ROLLOUT_S`)으로 실행합니다. 40초가 되면 작업 진행과 상관없이 정책을 멈춥니다.
- LeRobot 0.6.1은 기본값(`return_to_initial_position=True`)으로 모든 관절(그리퍼 포함)을 **3초 동안 시작할 때의 관절 값까지 직선으로 옮긴 뒤** 토크를 끕니다 (`rollout/strategies/core.py`).
- 그래서 테이프를 옮기던 중이어도 팔이 시작 자세로 돌아갑니다. ACT는 남은 시간을 모릅니다.

40초를 넘긴 이유
- 시연 사람은 테이프를 8.6~13.8초에 잡고, 10.6~18.2초에 놓고, 20~27초에 끝냈습니다.
- 실행할 때는 다음 이유로 더 오래 걸립니다.
  - 녹화 시작 직후 3~5초 동안 멈춰 있던 것까지 배워서 출발이 늦습니다.
  - 예측할 때마다 팔이 0.1~0.25초 멈춥니다.
  - 4-1, 4-2처럼 한 번에 못 집으면 다시 시도합니다.

**개선:**
- `ROLLOUT_S`를 60~90초로 늘리고, 작업이 끝나면 Ctrl+C로 멈춥니다. Ctrl+C로 멈춰도 시작 자세로 돌아갑니다.
- `--return_to_initial_position=false`는 권하지 않습니다. 끝날 때 토크가 꺼지기 때문에(`disable_torque_on_disconnect=True`) 팔이 그 자리에서 힘없이 떨어집니다.
- 녹화 시작 직후의 정지 구간을 줄이면(바로 움직이기, 또는 학습 전에 잘라 내기) 실행 시간도 줄어듭니다.

## 5. 정리

| 배운 것 | 근거 | 다음에 할 일 |
|---|---|---|
| 실패 원인은 학습이 아니라 데이터였다 | 1차·2차 모두 loss 정상 수렴, 1차 정지 65% | 녹화 직후 `ep_stats.py`로 정지 비율·시작 자세 확인 |
| 카메라는 작업 전체가 보이는 고정 위치에 | 1차 손목 1대 → 바구니가 안 보임 | 카메라 자리 표시, 녹화~실행 동안 고정 |
| 한 자리 15개면 그 자리에서는 된다 | 2차 15개로 성공 | 자리를 늘릴 때 양 끝 포함, 자리마다 10~20개 |
| 데이터에 없는 위치·자세는 못 한다 | 4-1 옆자리, 4-2 세운 테이프 | 위치·자세를 다양하게 녹화, 손목 카메라 검토 |
| ACT는 지금 화면만 보고 작업 단계를 정한다 | 4-2 놓는 동작 반복 | 단계마다 화면이 확실히 구별되게 (손목 카메라) |
| 실행 시간 제한은 스크립트가 건다 | 4-3, LeRobot 코드 | `ROLLOUT_S` 늘리기, 성공률 기록 |
| CPU 실행에서는 예측 간격이 부드러움을 좌우한다 | 예측 0.1~0.25초 동안 정지 | `n_action_steps`=chunk, 필요하면 비동기 실행 |

다음 실험 제안
